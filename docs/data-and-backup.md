# 数据存储、备份与回收站

Aion 所有数据 100% 存储在本地设备，不依赖云服务。本文档说明本地目录布局、受管附件、备份与恢复、Schema 升级及回收站清理机制。

## 数据目录结构

默认数据目录位于系统标准应用配置路径（macOS：`~/Library/Application Support/Aion/`；Windows：`%AppData%\Aion\`；也可通过 `-data-dir <路径>` 启动独立实例）：

```text
<数据目录>/
├── aion.sqlite          # SQLite 主数据库（Schema v3：项目、任务、子任务、求职投递与时间线、回收站、设置）
├── attachments/         # 受管本地附件存储
├── backups/             # 自动快照（auto-*.zip）与恢复前安全备份（safety-*.zip）
├── aion.sock            # 桌面端运行期间的本地 IPC Socket（退出自动清理，不纳入备份）
└── .updater-state.json  # 本机更新检查运行态（最近检查时间与已跳过版本，不随备份恢复覆盖）
```

> 注：若自定义 `-data-dir` 路径过长导致超过本地 Socket 路径长度限制，本地 IPC Socket 会自动回退到系统临时目录下的专属目录（macOS 为 `0700` 权限的 `/tmp/aion-ipc-<uid>/`，Windows 为 `%TEMP%\aion-ipc\`），并沿用非符号链接校验。求职网站图标的本地磁盘缓存独立存放在系统用户缓存目录（macOS 为 `~/Library/Caches/Aion/favicons/`，Windows 为 `%LocalAppData%\Aion\favicons\`），不占用数据目录且不纳入备份包。

## 本地受管附件

- 支持点击选择或直接从 Finder 拖入文件/图片，提供图片缩略图与大图预览、系统默认应用打开、Finder 定位与另存为导出。
- **暂存导入**：导入先在数据目录的私有暂存区完成复制、限额校验、哈希计算和同步，再短暂加锁确认目标任务可见并提交。若导入期间完成了备份恢复，需要重新导入。
- **另存为导出**：仅接受常规文件作为来源，并在数据锁外复制和校验内容；即使复制期间清理了原附件，已开始的导出仍可完成。

## 自动备份与手动导出

可在顶部导航胶囊的**设置**（快捷键 `⌘,`）中管理备份与恢复：

- **自动备份**：应用启动及运行期间按周期（默认每天一次、保留最近 7 份）自动生成一致性快照（`auto-*.zip`）并轮转清理旧备份。
- **历史备份记录**：设置页「自动备份」区域内置默认折叠的**历史备份记录**列表（由 `backup.Service.ListManagedBackups` 从本地 `.backup-auto-state.json` 无锁读取），按时间倒序区分「自动备份」与「安全备份」，支持在 Finder 中显示或直接触发恢复确认弹窗。
- **手动导出**：随时将当前 SQLite 快照、全部受管附件及 `manifest.json` 校验清单打包导出为 `.zip`。
- **并发与锁机制**：自动备份与手动导出只在生成 SQLite 快照、固定附件引用期间占用数据锁，压缩、校验和自动备份轮转均在锁外完成。临时附件引用采用同一文件系统的硬链接，保证并发删除附件不会破坏正在生成的备份，完成或取消后会清理。恢复前的安全备份仍与数据替换保持互斥，避免遗漏恢复前最后的修改。
- **目录与容量限制**：
  - 自动备份目录（含默认目录）不能是符号链接，也不能位于受管附件存储内。
  - V1 备份上限为：10,000 个附件、单文件（含数据库快照）256 MiB、解压后总计 2 GiB（导出时预留 2 MiB 清单空间）、ZIP 文件 3 GiB。
  - 导入附件时仅检查单附件大小；若数据累计超过整包限制，需另行处理。

## 完整恢复与 Schema 升级

- **版本与完整性校验**：完整恢复仅接受使用当前数据库结构（Schema v3）的备份包。恢复前会校验 `manifest.json` 清单、文件 SHA-256 摘要与数据库结构；版本不匹配、文件损坏或校验失败时恢复会中止。
- **状态保留**：已结束投递即使在结束后修正过阶段，恢复时也会同时保留修正后的阶段和原有结果。
- **恢复前安全备份**：正式替换前会自动将当前数据打包为一份 `safety-*.zip` 安全备份以便回滚。安全备份按生成顺序保留最近 5 份，并额外保护本次恢复所用的源文件。若生成安全备份后恢复失败，设置页会显示错误原因和该安全备份的路径。
- **本地自动升级**：首次启动新版时，本地数据库会自动升级到 Schema v3，删除投递的跟进日期列，并保留其他投递字段与时间线。Schema v1、v2 的旧备份无法在新版中恢复，升级后建议重新导出完整备份。

## 回收站与彻底删除

- 删除项目、任务与求职投递默认进入统一回收站，支持按类型筛选、带完整时间线恢复与彻底清除。
- **状态校验**：回收站操作会区分条目已不存在和条目状态冲突。若单独移入回收站的任务所属项目也在回收站中，可以一并恢复项目和任务，也可以单独彻底删除该任务。
- **分步清理与回滚**：彻底删除或清空回收站时，数据库删除与附件文件清理分步完成。清空回收站时，项目、任务和投递记录在同一事务中删除，任一模块删除失败都会回滚。若附件文件清理失败，条目仍会从回收站移除并显示警告，未引用文件会在后续清理操作中重试删除。
